# Cloudflare Workers 404 Fix - Root Cause Analysis & Solution

## 🔴 ROOT CAUSE OF 404 ERROR

The Cloudflare Worker was deployed successfully, but was returning **404 Not Found** because:

**`wrangler.jsonc` was missing the `main` field**

Without the `main` field, Cloudflare Workers didn't know which file to load as the Worker entry point. This meant:
- ✅ Worker deployed
- ✅ Assets served from dist/client
- ❌ NO server entry point defined
- ❌ Request to "/" had no route handler → 404

## ✅ FILES THAT ARE CORRECT

### dist/server/server.js
- **File size**: 38.66 KB
- **Exports**: `default` (fetch handler) + `createServerEntry`
- **What it does**: TanStack Start SSR server that handles all routes and renders React components
- **Export code**:
```javascript
const server = createServerEntry({ fetch });
export {
  createServerEntry,
  server as default
};
```

## ❌ FILES THAT WERE WRONG

### OLD wrangler.jsonc (MISSING main field)
```jsonc
{
  "name": "miment",
  // NO "main" field ← THIS WAS THE BUG!
  "compatibility_date": "2025-09-24",
  "assets": {
    "directory": "./dist/client"
  }
}
```

### dist/client/wrangler.json (Auto-generated by Vite, WRONG)
- Points to wrong location
- Has no `main` field
- Assets directory is "." (current dir) instead of proper path
- This file gets generated during build and is not the source of truth

## ✅ THE FIX

### 1. Updated wrangler.jsonc
```jsonc
{
  "$schema": "node_modules/wrangler/config-schema.json",
  "name": "miment",
  "main": "dist/server/server.js",  ← ADDED THIS
  "compatibility_date": "2025-09-24",
  "compatibility_flags": [
    "nodejs_compat_v2"
  ],
  "assets": {
    "directory": "./dist/client"
  },
  "env": {
    "production": {
      "name": "mim-crm-prod",
      "routes": []
    },
    "staging": {
      "name": "mim-crm-staging",
      "routes": []
    }
  },
  "vars": {
    "ENVIRONMENT": "production"
  }
}
```

### 2. Updated vite.config.ts
Added `cloudflare: { isWorker: true }` to tell Vite this is a Worker build:
```typescript
export default defineConfig({
  cloudflare: {
    isWorker: true
  },
  vite: {
    ssr: {
      external: ["workerd"]
    }
  }
});
```

## 🚀 DEPLOYMENT FLOW

1. **Local build**: `npm run build`
   - Generates `dist/server/server.js` with default export
   - Generates `dist/client/` with static assets
   
2. **Cloudflare deployment**:
   - Reads `wrangler.jsonc`
   - Finds `main: "dist/server/server.js"`
   - Loads the server entry point
   - Sets up asset serving from `./dist/client`
   - Routes all requests to the server handler

3. **Request handling**:
   - Request to `/` → server.js handles it
   - Server renders React router
   - Returns HTML with hydration
   - Client JavaScript takes over

## 📌 KEY LESSON

**For TanStack Start + Cloudflare Workers:**
- Must specify `main` field in wrangler.toml/jsonc
- Must point to `dist/server/server.js` or equivalent
- That file must export a `default` handler with `fetch` capability
- Assets must be in separate directory (./dist/client)
- The Cloudflare Vite plugin handles rest of the configuration
