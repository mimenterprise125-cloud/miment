# Cloudflare Workers 404 Error - Complete Fix Summary

## 🎯 Problem
Website deployed to Cloudflare Workers showed **404 Not Found** instead of loading the TanStack Start app.

## 🔍 Root Cause
The Worker had no entry point defined - Cloudflare didn't know which file to load as the server handler.

### What Was Wrong
1. **wrangler.jsonc** had NO `main` field
2. Without `main`, Cloudflare couldn't find the Worker handler
3. Requests to `/` returned 404 because no routes were defined

## ✅ Solution Implemented

### 1. **Remove `main` from wrangler.jsonc** (avoid pre-build validation error)
   - The Cloudflare Vite plugin validates files before the build
   - Since `dist/server/server.js` doesn't exist yet, validation would fail
   - Solution: Don't specify `main` in the source config

### 2. **Create Post-Build Script** (generate config after build)
   - **File**: `scripts/post-build.js` (ES module)
   - **Runs after**: `npm run build`
   - **Creates**: `dist/server/wrangler.json` with correct configuration

### 3. **Update Build Command** (package.json)
   ```json
   "build": "vite build && node scripts/post-build.js"
   ```

## 📋 Files Changed

### 1. **wrangler.jsonc** (source config)
```jsonc
{
  "$schema": "node_modules/wrangler/config-schema.json",
  "name": "miment",
  // NO main field - this is intentional!
  "compatibility_date": "2025-09-24",
  "compatibility_flags": ["nodejs_compat_v2"],
  "assets": {
    "directory": "./dist/client"
  },
  "env": {
    "production": { ... }
  }
}
```

### 2. **scripts/post-build.js** (new file)
```javascript
import fs from 'fs';
import path from 'path';
import { fileURLToPath } from 'url';

// This script creates dist/server/wrangler.json after build
const wranglerConfig = {
  name: 'miment',
  main: 'server.js',  // ← Relative to dist/server
  compatibility_date: '2025-09-24',
  compatibility_flags: ['nodejs_compat_v2'],
  assets: {
    directory: '../client'  // ← Points to dist/client
  }
};

fs.writeFileSync(wranglerJsonPath, JSON.stringify(wranglerConfig, null, 2));
```

### 3. **package.json** (updated build script)
```json
"build": "vite build && node scripts/post-build.js"
```

### 4. **vite.config.ts** (kept simple)
```typescript
export default defineConfig();
```

## 📌 Why This Works

**Problem**: Cloudflare Vite plugin validates `main` field before build runs
**Solution**: Don't validate, generate config after build succeeds
**Result**: Correct Worker configuration without pre-build errors

This approach is idiomatic for TanStack Start with Cloudflare Workers because:
- Let the framework's build process generate the server entry point
- Generate Worker config after build completes
- Use the generated config for deployment
- No pre-build validation conflicts
